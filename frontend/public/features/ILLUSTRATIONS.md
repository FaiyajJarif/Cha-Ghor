# Landing-page imagery

Fifteen photographs and fourteen SVG illustrations (unused fallbacks), used by `src/lib/site.js` on the
Landing and Features pages. Every card uses a photograph; the illustrations are kept as
ready-made fallbacks under matching names.

# Part 1 — Photographs

Every landing and Features card uses one of the four photographs in
`extras/images/` (`chabagan1`–`chabagan4`), cropped by
`extras/tools/build_photo_cards.py`.

**The photographs are used as they are.** No overlay, no text, no scrim — an
earlier revision composited brand chips and feature labels onto them and it was
removed. If you re-run the script, it only crops.

All thirteen cards are **560 × 244 (2.30)**, which is exactly the shape
`Landing.jsx` renders at (`h-40 w-full object-cover`), so nothing is cropped
there. `Features.jsx` uses `h-full w-full object-cover` in a taller column and
trims 60–80 px off each side — harmless now that nothing sits near an edge, but
worth knowing before you put anything back on top of these.

## ⚠ Licence — UNRESOLVED

**The source of these four photographs is not recorded, and nobody has confirmed
they are cleared for use.** Two specific reasons to settle this before the site
goes public or the report is submitted:

- `chabagan1.jpeg` carries a **Bangla caption watermark dated ১৫।০৪।২০১৭** in its
  lower right. A visible credit stamp usually means the photograph belongs to
  someone else. The 515 × 224 centre crop happens to fall above it, so the stamp
  is not in `workforce.jpg` — that was the framing that suited the three
  pluckers, **not** an attempt to remove the credit. Removing a photographer's
  watermark is not something to do.
- The photographs show **identifiable people**. Even with a licence, a portrait
  on a public marketing page is a separate question from a licence to copy.

## Resolution

The originals are 507–900 px wide, so the crops are too. The hero box is about
556 CSS px, which is 1112 device px on a retina screen — `hero.jpg` is 900 px, so
expect mild softness there. Upscaling would add bytes without adding detail, so
it has not been done. Replace with a larger original if it bothers you.

# Part 2 — Illustrations (fallbacks)

Not referenced by `site.js` right now. Each one matches a photograph by name,
so swapping any card back is a `.jpg` → `.svg` edit on one line.

## Provenance

**All of these were drawn from scratch for this project.** They are not stock
art, not traced from photographs, and contain no third-party asset. Every shape
is a hand-written SVG path in the site's own palette. There is nothing here to
attribute and no licence to comply with — which matters for a submitted
university project, where an unattributed stock photo is a real problem.

They were generated by a script (`extras/tools/gen_illustrations.py`), so the
whole set can be regenerated or restyled consistently rather than edited one file
at a time.

## Why vector and not photographs

- **Size.** The fourteen files together are about 90 KB. The single stock PNG
  they replaced was 2.2 MB on its own — more than twenty times the whole set,
  for one image.
- **Sharpness.** SVG is resolution-independent, so they stay crisp on a phone,
  on a projector, and in a printed report.
- **Consistency.** Every file shares the same layered-hill horizon and terrace
  contours, so the page reads as one designed thing instead of a collage.
- **No font dependency.** There is no `<text>` element anywhere in the set. An
  early version drew the Taka sign (৳) as text and it rendered as an empty box
  wherever that font was missing; it is drawn as paths now, so every viewer sees
  the same picture.

## Replacing one with a photograph

Drop a JPG or PNG into this folder and point the matching entry in
`src/lib/site.js` at it — for example `image: "/features/leaf.jpg"`. Match the
canvas ratio in the table above, keep it under about 300 KB, and if the photo is
not your own, record its source and licence here. Wikimedia Commons has
usable Creative Commons photographs of the Srimangal and Sylhet gardens; most
image-search results are not free to use, whatever the search page implies.

Setting an entry back to `image: ""` restores the green gradient placeholder.
